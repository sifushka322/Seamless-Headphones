# Проверка версии 0.2.0

Дата: 22 сентября 2026. Mac с Apple Silicon, SDK macOS 26.5; тестовый эмулятор Android 15 (API 35, arm64).

## Выполнено

- Скомпилированы все исходники Swift в настоящее приложение, целевая macOS 14.0; создан DMG.
- 20 проверок Swift-протокола: аутентификация, фрагментация, Unicode, повтор, чужая сессия, отражение, размер кадра, порядок этапов и тайм-аут.
- 27 проверок Swift-автоматики: новое воспроизведение, защита активного источника, звонка и удержания, свежесть данных, ручной приоритет, cooldown, пауза после ошибки, разрешения, одновременные старты, debounce и отсутствие отложенного перехвата.
- 7 Kotlin JUnit-тестов: протокол и детектор новых стартов, подавление коротких и заблокированных событий, восстановление исходного состояния. Общие синтетические протокольные векторы проверяются обоими языками.
- Android instrumentation: реальный холодный запуск Activity, навигация по четырём разделам, переход в тёмную тему, пересоздание Activity с сохранением темы и страницы. Тест проходит на API 35; получены скриншоты светлой, тёмной темы и автоматизации.
- `assembleDebug`, `testDebugUnitTest`, `connectedDebugAndroidTest`, `lintDebug` проходят. Lint: без ошибок, два предупреждения об иконке (v26-папка при minSdk31 и отдельная monochrome-иконка).
- Mac-интерфейс отрисован и визуально проверен в обеих темах через `--demo --light/--dark --render-preview`. Деморежим не запускает BLE и не меняет настройки, секреты или аудиоподключение; числа на его скриншотах синтетические.
- APK проверен `apksigner verify`, приложение — `codesign --verify --deep --strict`, DMG — `hdiutil verify`. Контрольные суммы приложены к сборкам.

## Исправлено при проверке

- Сбой Android при обращении к insetsController до установки content view; добавлен регрессионный UI-тест.
- Сохранение фильтра источников и задержки без подключённого сервиса.
- Возврат к началу страницы при смене Android-вкладки.
- Ширина Mac-навигации: длинное название раздела помещается в строку.
- Подавление событий на обоих устройствах во время ручного приоритета, cooldown, отсутствия разрешений и устаревших состояний.
- Обычное A2DP-подключение больше не принимается на Mac за доказательство владения аудиовыходом телефона.
- Повторная проверка условий автоматической передачи перед выполнением Android-команды.

## Не проверено на физическом комплекте

- BLE Mac ↔ Android, рекламирование, дальность, разрешения Bluetooth.
- Фактическое подключение/отключение конкретных наушников, запреты OEM на A2DP, реальная слышимость и задержка.
- Точность детектора воспроизведения в пользовательских плеерах, в том числе удерживающих открытый поток в паузе.
- Звонки/VoIP, multipoint, заблокированный телефон, энергопотребление и сон на реальных устройствах.
- Нотарификация Apple, release-подпись Android, публикация в магазинах, внешний аудит безопасности.

Сборка, эмулятор и unit-тесты не доказывают аппаратную совместимость. Для приёмки нужна последовательность из [scenarios.md](scenarios.md). Отказ системного A2DP API — ограничение совместимости, а не повод объявлять успешную передачу после одного отключения Mac.
